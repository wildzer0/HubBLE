# M3 manual hardware checklist (⛔ hardware gate: B68 + EM06 together)

Needed: the S3-Zero with the M3 build (OTA upload or first USB flash), a PC (USB), a phone for the web app, the
Yunzii B68 (Oblio firmware, Bluetooth mode) and the ProtoArc EM06 (stock, Bluetooth 5.x channel).
Pairing in M3 is Just Works; the web UI for pairing arrives in M5, so use `curl` (replace the IP/headers as needed):

```sh
H='-H X-HubBLE:1 -H Content-Type:application/json'
curl -X POST $H -d '{}' http://192.168.4.1/api/v1/pairing/scan
curl http://192.168.4.1/api/v1/pairing/scan            # wait, then read the results
curl -X POST $H -d '{"address":"aabbccddeeff","address_type":0}' http://192.168.4.1/api/v1/pairing/start
curl http://192.168.4.1/api/v1/devices
```

## A. Pair the B68

- [ ] Put the B68 in Bluetooth pairing mode (hold B/N/M for 3 s on a slot; the BLE name is `OBLIO`).
- [ ] The scan list shows `OBLIO` (or the stock name); pair it. `pairing/scan` state goes connecting -> pairing -> done.
- [ ] `GET /devices` shows it `connected`, `ready`, type `keyboard`. Note `boot_fallback` (should be false).
- [ ] Export its report map (`/devices/{id}/report-map`) and add it to `firmware/test/fixtures/yunzii-b68.hex`.
- [ ] If pairing fails with "encryption failed"/"passkey requested", note the exact log line (live log on the System page).

## B. Pair the EM06 trackball

- [ ] Same flow with the EM06 on its BT 5.x channel. Export its report map -> `firmware/test/fixtures/protoarc-em06.hex`.
- [ ] Both devices are connected at the same time.

## C. Forwarding (PC connected over USB)

- [ ] Typing on the B68 shows on the PC; Shift/Ctrl/Alt/GUI combinations work; no stuck keys.
- [ ] Media keys (Fn row / volume) work.
- [ ] Trackball: movement, buttons, scroll wheel and horizontal scroll (if present).
- [ ] Type while moving the trackball: both work simultaneously.
- [ ] Turn off the B68 while holding a key: the key is released on the PC (no stuck key).
- [ ] Caps Lock on the PC lights the B68's Caps indicator (LED sync); also after the B68 reconnects.

## D. Reconnect and persistence

- [ ] Power-cycle the B68 / let it sleep and wake it: it reconnects within a few seconds (watch `reconnects`).
- [ ] Unplug/replug the dongle: both devices reconnect on their own (bonds persisted).
- [ ] `DELETE /devices/{id}` forgets a device; it does not reconnect any more.
- [ ] A device that is not paired never connects (try the phone or another keyboard in pairing mode).

## E. Combos

- [ ] With the AP off, hold both Shifts for 3 s on the B68: the AP comes up (blue LED / SSID visible).
- [ ] Both Shifts + Esc for 10 s: the Wi-Fi password is reset to `hubble-setup` and the setup wizard shows again; bonds stay.

## F. Numbers to record (docs/latency.md)

- [ ] `connection.interval_ms` of each device (target 7.5 ms; note what the peripheral accepted) and `latency`.
- [ ] `latency_us` min/avg/p95/max per device after typing a paragraph (target added latency <= 15 ms).
- [ ] RSSI and battery values look plausible. Free heap on the System page with the AP on (target >= 60 KB).
- [ ] Note any Wi-Fi/BLE coexistence effect with the AP on.
