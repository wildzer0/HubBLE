# M1 manual hardware checklist (⛔ hardware gate, ESP32-S3-Zero)

Needed: the S3-Zero, a USB-C data cable, a phone or laptop with Wi-Fi, Python with `esptool`
(`pip install esptool`) and the files below. Default Wi-Fi password: `hubble-setup`.

Files (from the v0.2.0 release): `hubble-s3_zero-v0.2.0-factory.bin`. Test images are supplied separately:
`hubble-s3_zero-v0.2.1-rc.1-ota.bin` (good) and `hubble-s3_zero-v0.2.1-rc.2-ROLLBACK-TEST-ota.bin` (its
self-test always fails).

## A. First flash and first boot

- [ ] Hold BOOT, plug in USB, release BOOT. Flash: `esptool.py --chip esp32s3 write_flash 0x0 hubble-s3_zero-v0.2.0-factory.bin`
- [ ] Unplug/replug. LED flashes white ~0.3 s.
- [ ] Serial log (USB Serial/JTAG port, e.g. `python -m serial.tools.miniterm /dev/ttyACM0 115200`) shows the banner
      `HubBLE firmware v0.2.0`, `AP on: SSID HubBLE-XXXX`, `HTTP server up`, `self-test passed`.
- [ ] Note the free heap shown on **System → Free internal RAM** (target ≥ 60 KB with the AP on).

## B. Wi-Fi, captive portal, web app

- [ ] Phone sees `HubBLE-XXXX` (XXXX = last 4 hex digits of the MAC) and joins with `hubble-setup`.
- [ ] The phone offers to "sign in to the network" / opens the portal automatically; otherwise open `http://192.168.4.1`.
- [ ] `http://hubble.local` also opens the app (works on iOS/macOS/Windows/most Android browsers; Android may not resolve `.local`: use the IP).
- [ ] Dashboard shows version `0.2.0`, board `s3_zero`, "Setup required" notice.
- [ ] **System → Change password** to a new 10+ character password. The phone drops off Wi-Fi; rejoin with the new one.
      The "Setup required" notice is gone.
- [ ] **System → Live log** shows new lines; **Download log** saves `hubble.log`.
- [ ] Language switch EN/IT works.

## C. OTA update (the gate)

- [ ] **Update**: running `0.2.0`, other slot empty. Upload `hubble-s3_zero-v0.2.1-rc.1-ota.bin`.
- [ ] Progress bar advances; page says the dongle is restarting, then "back online, running 0.2.1-rc.1".
- [ ] After a few seconds **Update** shows last result "running 0.2.1-rc.1, self-test passed", other slot `0.2.0`.
- [ ] Uploading the same file again works (or is refused only while an image is pending verify).
- [ ] Negative test: upload a random/truncated file → rejected with an error, dongle keeps running.

## D. Forced rollback (the gate)

- [ ] Upload `hubble-s3_zero-v0.2.1-rc.2-ROLLBACK-TEST-ota.bin`. It installs and reboots into `0.2.1-rc.2`.
- [ ] While it runs (≤ 60 s) the web app works; the log says `self-test forced to fail`.
- [ ] After ~60 s the dongle reboots by itself into `0.2.1-rc.1`; the LED blinks red 3 times after the white flash.
- [ ] **Update** shows "rolled back: self-test failed" and the rollback notice.

## E. Download mode

- [ ] **System → Reboot to USB download mode** (confirm). The serial port changes to the ROM bootloader
      (`esptool.py --chip esp32s3 chip_id` works without pressing BOOT). Unplug/replug returns to normal.

## F. Optional: AP timeout

Needs a test build (`HUBBLE_OVERLAY=ap_timeout_test`, which pretends a BLE device is bonded): the AP stays on 5 min
after power-up, stays on while the web app is open, and switches off 3 min after you close it.

Record deviations (LED colours, GPIO, timings, heap) in `docs/hardware.md`.
