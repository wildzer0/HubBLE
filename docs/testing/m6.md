# M6 manual hardware checklist (signed OTA, check for updates)

Needs a dongle that is already running a **signed** build (flash a locally built `factory.bin` once over USB; the
development key is fine) and, for section C, a public GitHub release of this repository (so it can only be completed
after the first push, at M8 or with a private test fork configured through `CONFIG_HUBBLE_UPDATE_REPO`).

## A. Signature checks on upload (local, no GitHub)

- [ ] Build v-A and v-B with the same development key. Upload v-B to a dongle running v-A: installs, boots, self-test passes.
- [ ] Build v-C with ANOTHER key (`HUBBLE_SIGNING_KEY=other.pem`). Uploading it is refused (`validation failed`), the dongle
      keeps running and the other slot is not selected.
- [ ] Take a build made before M6 (unsigned, or an image with the signature block cut off). Upload is refused.
- [ ] Flip a byte in a signed image: refused (checksum/hash or signature).
- [ ] Migration: a dongle still running a pre-M6 build accepts the first signed image.

## B. Wi-Fi network for updates

- [ ] Settings: save a network; the field never shows the password again and a backup file does not contain it.
- [ ] Wrong password: the check ends with "Could not join the Wi-Fi network" in about 20-60 s, the AP stays reachable.
- [ ] Note what the phone does while the dongle joins the router (the AP may move to the router's channel). Record it.
- [ ] After the check the dongle leaves the network (router client list) and the AP returns to its own channel.

## C. Check and install from GitHub (needs a release)

- [ ] Stable channel finds the newest non-pre-release; pre-release channel finds the newest release of any kind.
- [ ] Release notes link opens. "Up to date" when the running version equals the release.
- [ ] Install with *Require physical confirmation* ON and a paired keyboard: the page asks for both Shifts (3 s); without the
      gesture it fails after 30 s with a clear message; with the gesture the download starts.
- [ ] Typing and the trackball keep working during the download (note any hiccup; `docs/latency.md` input).
- [ ] After the reboot the new version runs, the self-test passes, the page reports the new version.
- [ ] Offer an older release: it can only be installed after ticking the downgrade confirmation.
- [ ] A release whose `min_version` is higher than the running version is refused with the "install an intermediate release" text.
- [ ] Block GitHub (airplane router) mid-download: the install fails cleanly, the running image is untouched.
- [ ] Heap: System page shows at least 60 KB free internal RAM while idle after a check (TLS buffers are freed).
