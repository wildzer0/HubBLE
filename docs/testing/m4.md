# M4 manual hardware checklist (secure pairing)

Same setup as `m3.md`. Watch the live log (System page) and the `pairing` object of `GET /api/v1/pairing/scan`.
All steps use the REST API until the web app pages arrive in M5.

## A. Keyboard with passkey (B68)

- [ ] Start a scan, pick the B68, start pairing. State `pairing`, `passkey` appears (6 digits, zero padded).
- [ ] Type the passkey on the B68 and press Enter. State goes to `bonded`, `level` is `green`. If the B68 never asks for a
      passkey (Just Works) or fails, note the exact log lines: it then goes through quarantine (section B) or fails.
- [ ] A wrong passkey fails the pairing (`security_failed`) and leaves no device in `GET /devices`.

## B. Quarantine challenge

- [ ] Pair the EM06: state `quarantine`, `challenge.kind` `clicks`, a sequence like `LRRLMR`.
- [ ] While in quarantine, moving the trackball and clicking does NOT move the host pointer or click.
- [ ] Perform the clicks within 30 s: `progress` advances, state `bonded`, level `yellow`.
- [ ] Wrong clicks restart the sequence; three mistakes fail the pairing and the device is not registered.
- [ ] Let the 30 s run out: pairing fails with `timeout`, the bond is deleted (the trackball can't reconnect).
- [ ] Keyboard Just Works (if the B68 uses it): `challenge.kind` `code`; typing the 6 characters passes.

## C. Physical confirmation

- [ ] With the B68 already paired and the setting on, pair the EM06: after the click challenge the state is `confirm`.
      Hold both Shifts on the B68 for 3 s: state `bonded`. Without the gesture it fails with `timeout` after 30 s.
- [ ] `PUT /settings {"require_confirmation": false}`: the next pairing skips `confirm`.
- [ ] First pairing with no keyboard paired: no confirmation is asked.

## D. Legacy policy

- [ ] If a device pairs with legacy keys: it is refused with `legacy_rejected` by default.
- [ ] Repeat with `"allow_legacy": true`: pairs, `level` is `red`.

## E. Rate limiting and cleanup

- [ ] Three failed pairings in a row: the fourth `start`/`scan` returns 429 `pairing_locked`; after 60 s it works again.
- [ ] `DELETE /devices/{id}` of a bonded device: it can no longer connect; a failed pairing never leaves a device in the list.
- [ ] Reboot the dongle: paired devices keep their `security` badge.
