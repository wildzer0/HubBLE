# M2 manual hardware checklist (ESP32-S3-Zero)

Needed: the S3-Zero flashed with the **debug_usb** build (`HUBBLE_OVERLAY=debug_usb tools/build-firmware.sh s3_zero`,
installed via the first USB flash or OTA upload), a PC, a phone for the web app. M1's checklist (docs/testing/m1.md)
is still pending and should be run first with the release build.

Inject input with (replace `<ip>`; the AP password is the one you set):

```sh
curl -X POST http://192.168.4.1/api/v1/debug/input -H 'X-HubBLE: 1' -H 'Content-Type: application/json' \
  -d '{"kind":"key","keys":[4]}'
```

## A. Enumeration

- [ ] Plug the dongle into the PC: it appears as a keyboard + mouse ("HubBLE", VID 303A). Linux: `lsusb`, `dmesg`.
- [ ] `usb_state` is `configured` in **System** and `/api/v1/status`.
- [ ] Linux: `sudo lsusb -v -d 303a:4001` shows two HID interfaces (boot keyboard, none).

## B. Reports (focus a text editor)

- [ ] `{"kind":"key","keys":[4]}` types `a`; `{"kind":"key","modifiers":2,"keys":[4]}` types `A`.
- [ ] `{"kind":"consumer","usage":233}` raises the volume (233 = 0xE9), 234 lowers it, 226 mutes.
- [ ] `{"kind":"mouse","dx":100,"dy":0}` moves the pointer right; `buttons:1` clicks; `wheel:-3` scrolls; `pan:3` scrolls sideways.
- [ ] Large movement (`dx:5000`) moves smoothly, nothing lost.
- [ ] Caps Lock on the PC: `keyboard_leds` in `/api/v1/diagnostics` becomes 2 (Num Lock 1, Scroll 4).

## C. BIOS/UEFI

- [ ] Enter the PC's BIOS/UEFI setup; injected keys navigate the menu (boot keyboard works without a driver).

## D. Suspend / resume / wakeup

- [ ] Put the PC to sleep: `usb_state` becomes `suspended` (check after wake). On resume it returns to `configured`.
- [ ] With remote wakeup enabled in the OS (Device Manager / `power/wakeup`), injecting a key while the PC sleeps wakes it;
      the waking key is not typed. (Some PCs cut USB power in sleep: note this.)

## E. OTA and download mode with TinyUSB

- [ ] OTA upload of a build still works and the new image passes the self-test (`usb_hid` is in the log).
- [ ] **System -> Reboot to USB download mode** makes the board show up as the ROM downloader (`303a:1001`,
      `esptool.py chip_id` works) without pressing BOOT. **Verify this carefully**: it depends on the PHY being
      handed back to the USB Serial/JTAG after the reset.
- [ ] After a power cycle the dongle returns to normal HID operation.
